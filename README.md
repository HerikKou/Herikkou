## Projetos em Destaque

### 🏦 FlowBank — Aprovação de Limite de Crédito com BPMN
> 🔗 [github.com/HerikKou/FlowBank](https://github.com/HerikKou/FlowBank)

**Problema:** processos de aprovação de crédito têm várias etapas (solicitação, análise de risco, decisão, registro), e quando as regras ficam espalhadas pelo código o fluxo se torna difícil de entender e auditar.

**Solução:** API backend em **Monólito Modular** em que o fluxo de aprovação é modelado em **BPMN (Flowable)**, com User Task, Service Task e Exclusive Gateway. Funcionários se autenticam com **Spring Security + JWT**, analisam solicitações e decidem com justificativa. Cada aprovação registra funcionário, score, solicitação e data, o que garante auditoria completa.

**Integração com Flowable:** o processo de aprovação é um modelo BPMN executado pelo engine do Flowable. Cada etapa chama componentes Java (Service Task), a análise do funcionário é uma User Task e o Exclusive Gateway direciona o fluxo conforme a decisão.

**Destaques:** orquestração visual do processo · autenticação stateless · trilha de auditoria · **deploy real em AWS EC2** com Docker Compose · decisões arquiteturais e trade-offs documentados (monólito modular vs. microsserviços, EC2 vs. ECS/EKS, Postgres em container vs. RDS).

`Java 21` `Spring Boot` `Spring Security` `JWT` `Flowable BPMN` `PostgreSQL` `Docker` `AWS EC2`

### 🛒 Loja PIX com IA — E-commerce com Mercado Pago e Análise de Vendas
> 🔗 [github.com/HerikKou/loja-pix-IA](https://github.com/HerikKou/loja-pix-IA)

**Problema:** lojas precisam receber pagamentos PIX com confirmação automática e ainda acompanhar estoque e desempenho de vendas sem analisar tudo manualmente.

**Solução:** API REST de e-commerce com cadastro de produtos, vendas com baixa automática de estoque e **pagamento PIX com QR Code via Mercado Pago**, confirmado por **webhook**. Uma rotina diária em **Spring Batch** gera notificações de estoque baixo, registra vendas e usa a **Claude (via Spring AI)** para produzir um resumo analítico do dia para a gerência. O acesso é controlado por perfis (VENDEDOR e GERENTE) com JWT.

**Integração com o Mercado Pago:** a API cria a cobrança PIX pelo SDK Java (API de Orders) e devolve o QR Code em base64. Quando o cliente paga, o Mercado Pago chama o webhook da aplicação, que marca o pagamento como `PAGO` e atualiza o total vendido do funcionário.

`Java 17` `Spring Boot` `Spring Security` `Spring Batch` `Spring AI` `Mercado Pago` `PostgreSQL` `Docker`

### 💳 Análise de Crédito com IA
> 🔗 [github.com/HerikKou/Limites-de-credito-com-IA](https://github.com/HerikKou/Limites-de-credito-com-IA)

**Problema:** o banco libera o limite, mas não explica se uma nova compra é compatível com a situação financeira real da pessoa.

**Solução:** 5 microsserviços orientados a eventos que avaliam uso do limite, tempo de histórico, atrasos e consultas ao CPF, calculam um score de risco e usam LLM para transformar a análise em linguagem natural. Quando o risco é alto, o usuário recebe um e-mail com a explicação.

| Serviço | Responsabilidade |
|---|---|
| `CreditoService` | Registra dados financeiros e publica eventos no Kafka |
| `HistoricoService` | Consolida o total gasto e calcula a exposição financeira |
| `ScoreService` | Calcula o score de risco com 4 critérios comportamentais |
| `LLMService` | Gera a explicação humanizada via Claude API |
| `NotificacaoService` | Envia e-mail quando o risco é elevado |

**Padrões:** Database per Service · Idempotência · Retry com backoff · Dead Letter Queue · Cache em memória

`Java 17` `Spring Boot` `Apache Kafka` `PostgreSQL` `Claude API` `Docker` `Datadog` `JUnit` `Mockito`

### 💸 Devolução de Pagamento PIX com IA
> 🔗 [github.com/HerikKou/Devolucao-de-Pagamento](https://github.com/HerikKou/Devolucao-de-Pagamento)

**Problema:** ao abrir uma disputa por PIX enviado por engano, o cliente recebe aprovação ou reprovação sem nenhuma explicação.

**Solução:** 7 microsserviços que calculam um score de credibilidade com base na frequência e no histórico de disputas. **A IA não decide:** a decisão vem das regras de negócio, e o LLM apenas traduz os fatores da análise em uma explicação clara para o cliente. Todo o fluxo é registrado para auditoria.

**Padrões:** Retry com backoff exponencial · Dead Letter Topic · Idempotência · Database per Service

`Java 17` `Spring Boot` `Apache Kafka` `PostgreSQL` `Claude API` `Docker` `Datadog`

### 🧾 Plataforma de Gestão de Boletos
> 🔗 [github.com/HerikKou/Plataforma_de_Gestao_de_Boletos](https://github.com/HerikKou/Plataforma_de_Gestao_de_Boletos)

**Problema:** boletos vencem sem que o usuário perceba, e o custo vai além do juro: multa, negativação e burocracia.

**Solução:** 4 microsserviços que automatizam o ciclo do boleto, da emissão ao pagamento automático, com alertas por e-mail 3 dias antes do vencimento e aplicação automática de juros. O estado de cada boleto é controlado por uma **State Machine** (`CRIADO → PRÓXIMO_VENCIMENTO → VENCIDO → PAGO`), e o e-mail do usuário fica isolado em um único serviço por privacidade.

**Padrões:** State Machine · Idempotência · Retry · DLT · Isolamento de dados sensíveis

`Java 21` `Spring Boot` `Apache Kafka` `PostgreSQL` `Spring Mail` `Thymeleaf` `Docker` `JUnit` `Mockito`
